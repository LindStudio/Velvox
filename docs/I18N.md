# Sprachen (Deutsch / English) – Regeln und Glossar

Seit 1.0 zeigt Headliner jede Oberfläche auf Deutsch oder Englisch. Standard ist die Sprache des Computers
(Windows-Anzeigesprache Deutsch → Deutsch, sonst Englisch). Gewählt wird beim allerersten Start (Willkommenskarte)
und jederzeit im Zahnrad-Menü (Einstellungen: Automatisch | Deutsch | English). Die Sprache ist eine Einstellung
des Nutzers (`Velvox.settings`, Schlüssel `language`), nie Teil eines Projekts, und ändert nie den Klang.
Ein Wechsel baut die ganze Oberfläche neu auf (`VelvoxAudioProcessorEditor::rebuild`), Ansicht und Auswahl bleiben.

## Code

`Source/Text/I18n.h`:

| Fall | So |
|---|---|
| Text, der sofort angezeigt wird (Beschriftung, Tooltip, Menü, Hinweis) | `i18n::tr ("Deutsch", "English")` |
| Text mit Zahlen/Werten | `i18n::format (i18n::tr ("{0} von {1} s", "{0} of {1} s"), { a, b })` – keine zerstückelten Sätze |
| Dezimalzahl im Fließtext | `i18n::number (x, 1)` (Deutsch `3,5`, Englisch `3.5`) |
| Text, der gespeichert und später angezeigt wird (Auto-Mix-Bericht, alles in `AutoMixController::Report`) | `i18n::both ("Deutsch", "English")`, Zahlen darin `i18n::numberBoth (x, 1)`; teile lassen sich mit `+` verketten |
| Anzeige eines evtl. gepackten Texts | `i18n::show (text)` (normaler Text bleibt unverändert – alte Projekte zeigen ihren deutschen Bericht) |
| Parameter-Name/-Beschreibung/-Auswahl in der Oberfläche | `i18n::paramName (id, englisch)`, `paramDescription`, `choiceName` (`Source/Text/ParamText.*`). **Der Host sieht immer die englischen Namen** aus `ParameterLayout.cpp` – dort nichts übersetzen |

- Literale sind UTF-8 (Build mit `/utf-8`); `tr` erwartet UTF-8.
- Nie Text bei statischer Initialisierung übersetzen (`static const` Tabellen mit `tr` werden nur einmal gebaut) –
  Tabellen als Funktion, die bei jedem Aufruf `tr` nutzt, oder Tabellen mit beiden Sprachen.
- Texte, die Daten sind (Parameter-Auswahlnamen für die Zuordnung, Preset-Namen, Modul-IDs) nicht übersetzen;
  nur die Anzeige.
- Tests laufen auf Deutsch (TestMain setzt `language = de`). Englisch prüfen mit `i18n::ScopedLanguage en (i18n::Language::english);`.
  Screenshots: Umgebungsvariable `HEADLINER_LANG=en`.

## Stil

- Deutsch: du-Form, kurz, klar, keine Werbefloskeln, keine Anglizismen, wo es ein gängiges deutsches Wort gibt.
- Englisch: US-Englisch (analyze, color), gleich kurz und direkt. Kein Marketing.
- Beide Sprachen sagen dasselbe – keine Zusatzinfos in nur einer.
- Großschreibung wie bisher: Knopf-/Reglernamen in Großbuchstaben, wo das Design sie so zeigt.

## Bleibt in beiden Sprachen gleich

Produkt- und Modulnamen (Headliner, EQ, Compressor, De-Esser, Level Ride, Vocal Smash, Smooth, Saturation, Doubler,
Choir, Pitch, Delay, Reverb, Stutter, Pulse, Vocal Check, Output), Preset-Namen, AUTO MIX, VOCAL CHECK, ADVANCED,
Bypass, Solo, Send/Insert (als Begriff), Sidechain, LUFS/dB/Hz/ms.

Übliche Audio-Fachbegriffe bleiben Englisch: Threshold, Ratio, Attack, Release, Knee, Makeup, Gain, Mix, Drive,
Decay, Pre-Delay, Feedback, Width, Low Cut, High Cut, Bell, Low/High Shelf, Notch, Band Pass, Tilt, Q, Ducking.
