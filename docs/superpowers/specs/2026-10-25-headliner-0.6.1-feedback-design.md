# Headliner 0.6.1 – user feedback round (design)

Source: user test of 0.6.0 (2026-10-25). Binding for the 0.6.1 tracks. The 0.6 spec
(`2026-10-25-headliner-pro-overhaul-design.md`) and its rules (stable parameter IDs, old projects sound identical,
real-time safety, gestures, undo, no permanent explanatory text) still apply.

## Items (user's words, then the decision)

1. **EQ band solo ("Kopfhörer wie Pro-Q 4").** Each EQ band gets a headphone button (in the selected-band row and on the
   band's hover/handle). While held/active you hear only that band's region: a band-pass around the band's frequency
   with the band's Q (for shelves/cuts: the region the band acts on), level-matched, no gain applied. Like Pro-Q, it is
   a monitoring state: not a parameter, not saved, not automatable, not an undo step; turning it off or closing the
   panel/plugin ends it. Clicks-free switch (short crossfade).
2. **Simple mode must set the modules, not add a hidden layer.** Bug: reverb off in Advanced, but reverb still audible
   because the Simple SPACE slider is up (Macros.cpp `applyMacros` adds mix and forces modules on).
   Decision: moving a Simple slider writes the module parameters directly (reverb mix, delay mix, ducking, EQ role
   bands, comp, sat …), one undo step per gesture, so the Advanced panels show exactly what you hear and a module
   switched off stays silent. The Simple sliders show a value derived from the module state they control (or their
   last set value; builder's call) – never a second offset. Old projects with non-zero macro values must sound
   identical: on load, bake the macro offset once into the module parameters (exactly what `applyMacros` produced) and
   zero the macros; record this in the CHANGELOG "Alte Projekte". Automation of the old macro parameters: keep them
   registered; builder rules how an automated macro behaves (recommended: still maps into module params).
3. **Chain scrolls horizontally** when many modules are loaded (wheel / shift-wheel / trackpad, drag of the strip,
   and the selected tile is scrolled into view). Nothing may be cut off or unreachable at any window size.
4. **Module solo with one click** ("alle bypassen, nur das eine spielt"): a solo control on each chain tile (e.g.
   Alt+click or an "S" that appears on hover – builder's call, must be discoverable via hover card) and in the panel
   header. Solo = all other modules bypassed (latency kept, no level jump beyond the module's own effect), only one
   solo at a time, click again to release. Monitoring state like item 1: not saved, not an undo step; the chain
   shows clearly that solo is active.
5. **Saturation: hear single bands.** In multiband mode each band (low/mid/high) gets a solo (headphone) button:
   only that band's processed output is heard. Same monitoring rules as item 1.
6. **Saturation Mix as a main control.** `satMix` (exists) moves into the main row ("MIX"), not only in Mehr.
7. **Auto-mix EQ does more than a low cut:** it sets individual boosts/cuts, including very narrow-Q cuts for
   resonances (surgical notches, Q up to ~10-16) and broad tonal moves, based on the vocal analysis (profiler spectrum
   vs. target curve, resonance detection on sustained peaks). Limits: max ~6 bands used by the auto-mix, cuts up to
   about −9 dB narrow / −4 dB broad, boosts up to about +4 dB broad, never boost narrow. Uses the role-band mechanism
   (`findOrCreateEqBand`) so user bands are not overwritten. Must improve the objective auto-mix score on the VocalSet
   val split and dry test vocals vs. 0.6.0 (no regressions on existing goldens beyond documented, justified shifts).

## Tracks
- `chain`: items 3 + 4 (ChainView, processor/VocalChain solo routing).
- `audition`: items 1 + 5 + 6 (EQ + Saturation DSP listen paths and panels).
- `macros`: item 2 (Macros, SimpleView, state migration, AutoMix interplay).
- `autoeq`: item 7 (AutoMix planner / profiler EQ decisions, bench).
